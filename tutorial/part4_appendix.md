# APPENDIX - Integration of robust longitudinal grey and white matter reconstruction

The here presented robust longitudinal quantitative tractography
framework follows a similar reconstruction strategy as various robust
longitudinal grey matter pipelines that also operate within an unbiased
within-subject template. This similarity can be leveraged to integrate
both robust longitudinal grey and white matter pipelines into a comprehensive framework 
to study neuroanatomical change.

The following sections will exemplify how the presented longitudinal
quantitative tractography framework can be integrated with FreeSurfer's
longitudinal processing stream. The key idea is to generate spatially
aligned T1-weighted and FOD within-subject templates and then use those
common templates and transforms within each pipeline. Specifically, we
will outline how to generate (rigid and non-linear) within-subject templates that live
in the same image space as the ones generated by the longitudinal
FreeSurfer pipeline, so that no or only minimal modifications to the
FreeSurfer workflow are required.

The provided commands are written to **replace steps 2.1 and 2.2.1**
(construction of within-subject templates & reconstruction of the
T1-weighted template) within the main tutorial.

> [!NOTE]
> The here described integrated workflow was first introduced in a separate article [Pruckner2025](https://academic.oup.com/brain/advance-article/doi/10.1093/brain/awaf344/8256350?login=false).
> If you follow the processing steps outlined below, please also cite this work accordingly.
>
> Also note that the upcoming code sections make extensive use of algorithms from software packages other than MRtrix3.
> Remember to also cite the relevant articles for the specific methods used (e.g., ```mri_synthstrip```, ```mri_robust_template```, ```ANTs```, and the ```longitudinal FreeSurfer pipeline```).


## 4.1 Within-subject template generation

**\[pipeline-specific processing\]**

First, we are going to reconstruct T1-weighted and FOD within-subject
templates that live in the same space as outputs from longitudinal
FreeSurfer. Template generation within this pipeline is achieved through
the command ```mri_robust_template```[[Reuter2016](https://pmc.ncbi.nlm.nih.gov/articles/PMC3389460/)], a symmetric,
outlier robust rigid registration algorithm. Hence, we will use the same
command to rigidly align T1-weighted images in our quantitative
tractography pipeline, and then optionally refine spatial alignment
through non-linear registration. 

Specifically, we will outline three registration strategies to derive
the relevant within-subject templates/transforms:

1.  **Rigid registration based on T1-weighted information,** using
    FreeSurfer's robust template registration.

2.  **Rigid registration + non-linear refinement based on T1-weighted
    information,** using FreeSurfer's robust template registration for
    rigid alignment, and ANTs' SyN for affine/non-linear registration.

3.  **Rigid registration based on T1-weighted information + non-linear refinement based on T1-weighted
    and ODF information,** using FreeSurfer's robust template
    registration for rigid alignment, and MRtrix3's multicontrast
    registration for affine/non-linear registration.

If only rigid registration is performed, the default longitudinal FreeSurfer processing stream can be executed as is; 
if non-linear refinement is performed, however, the updated template needs to be injected into the longitudinal processing stream
so it is reconstructed instead. The final transforms are then applied to T1-weighted and FOD images, which are averaged to
unbiased within-subject templates. 

To conveniently perform these registrations, you can make use of the
wrapper provided through this repository (scripts/unbiased_template.py), which will automatically
generate the T1-weighted template, FOD template and transforms in
MRtrix3 format.

> [!TIP]
> The following registrations will use the (skull-stripped)
> ```T1w_norm_Warped.nii.gz``` files as inputs, which were automatically
> generated by ANTs during cross-modality registration within sessions.
> This means, they are spatially aligned with session-wise DWI data but
> have been resampled to their resolution, which typically is lower than
> the native resolution of T1-weighted images. To generate
> *full-resolution* within-subject templates, one can also apply the
> derived transform manually to the T1-weighted image *without*
> resampling, and provide those images as input to the command (if ODFs
> are also used, they will need to be upsampled onto this
> higher-resolution grid). Full-resolution registration should be
> considered if large morphological changes are expected between sessions,
> or if registration quality is found to be insufficient.

### 4.1.1 Skull-strip T1-weighted images

First, let's extract the brain from the T1-weighted images that will
serve as input for registration:

```bash
for_each tp* : mri_synthstrip \
  -i IN/T1w_norm_Warped.nii.gz \
  -o IN/T1w_norm_Warped_brain.nii.gz
```

### 4.1.2 Rigid registration based on T1-weighted information

**\[pipeline-specific processing\]**

The following command will perform rigid registration using FreeSurfer's
```mri_robust_template```, convert the linear transforms to MRtrix3 format,
apply them to T1-weighted and FOD images (including reorientation and
modulation), and average the spatially aligned images to unbiased
within-subject templates.

To perform these operations run:

```bash
python unbiased_template.py \
  --t1w tp1/T1w_norm_Warped_brain.nii.gz tp2/T1w_norm_Warped_brain.nii.gz \
  --session_labels tp1 tp2 \
  --out_dir template \
  --odf tp1/wmfod_norm.mif tp2/wmfod_norm.mif fod_template.mif
```

> [!NOTE]
> The output FOD template is **not constructed through FOD-based** but
> T1-weighted registration; this is not necessarily a problem, but
> something to be aware of. 

### 4.1.3 Non-linear registration based on T1-weighted information

**\[pipeline-specific processing\]**

The following command will perform rigid registration using FreeSurfer's
```mri_robust_template```, and affine/non-linear refinement using ANTs
```antsMultivariateTemplateConstruction2.sh```. The obtained transforms will
be converted to MRtrix3 format and composed, and then applied to
T1-weighted and FOD images (including reorientation and modulation).
Finally, spatially aligned images are averaged to unbiased
within-subject templates.

To perform these operations run:

```bash
python unbiased_template.py \
  --t1w tp1/T1w_norm_Warped_brain.nii.gz tp2/T1w_norm_Warped_brain.nii.gz \
  --session_labels tp1 tp2 \
  --out_dir template \
  --refine_nonlinear ants \
  --odf tp1/wmfod_norm.mif tp2/wmfod_norm.mif fod_template.mif
```

> [!NOTE]
> The output FOD template is **not constructed through FOD-based** but
> T1-weighted registration; this is not necessarily a problem, but
> something to be aware of.


### 4.1.4 Non-linear registration based on T1-weighted and ODF information

**\[pipeline-specific processing\]**

The following workflow will perform rigid registration using
FreeSurfer's ```mri_robust_template```, and affine/non-linear refinement using
MRtrix3's ```population_template```. The obtained transforms are then
converted to MRtrix3 format and composed, and applied to T1-weighted and
FOD images (including reorientation and modulation). Finally, the
spatially aligned images are averaged to unbiased within-subject
templates.

For the command to run properly, the orientation distribution functions
(ODFs) and T1-weighted contrasts of a given session must have the same
dimensions and intensity ranges; the latter is important so that the
registration cost is not dominated by modalities with higher tissue
intensities.

To intensity scale the T1-weighted image to ODF data:

```bash
mkdir -p template/t1w_input/

for_each tp* : sh -c '
  mrconvert IN/wmfod_norm.mif IN/tmp_wm.mif -coord 3 0
  mrcalc IN/tmp_wm.mif IN/gm_norm.mif -add IN/tmp_wm_gm.mif
  mrcalc IN/tmp_wm_gm.mif IN/csf_norm.mif -add IN/tmp_all.mif

  mrhistmatch \
    linear \
    IN/T1w_norm_Warped_brain.nii.gz \
    IN/tmp_all.mif \
    template/t1w_input/PRE.nii.gz

  rm IN/tmp*'
```

To generate the nonlinear templates and transforms run:

```bash
python unbiased_template.py \
  --t1w template/t1w_input/tp1.nii.gz template/t1w_input/tp2.nii.gz \
  --session_labels tp1 tp2 \
  --out_dir template \
  --refine_nonlinear mrtrix3 \
  --odf tp1/wmfod_norm.mif tp2/wmfod_norm.mif fod_template.mif \
  --odf tp1/gm_norm.mif tp2/gm_norm.mif gm_template.mif \
  --odf tp1/csf_norm.mif tp2/csf_norm.mif csf_template.mif \
  --mrtrix3_multicontrast_weights 1 1 0.5 0.0001 \
  --mrtrix3_masks tp1/dwi_mask_upsampled.mif tp2/dwi_mask_upsampled.mif
```

> [!NOTE]
> Here coregistration weights of 1,1,0.5,0.0001 are specified, defining
> the weighted contribution of each image contrast to the registration
> cost (corresponding to order of the input contrasts, with T1-weighted
> required to be first). In this configuration, affine and non-linear
> registration is primarily driven by the T1-weighted images and WM ODFs,
> with a moderate contribution from GM ODFs. The reasoning of this
> specification is that T1-weighted contrasts, and to a lesser extent also
> GM ODFs, provide meaningful information for the alignment of cortical
> and subcortical structures, whereas WM ODFs provide meaningful
> information for the alignment of the deep white matter. CSF ODFs on the
> other hand contain little spatially specific information and were
> therefore strongly downregulated in their contribution to the
> regularisation cost (nonetheless, they were included to additionally
> derive an output CSF template). Note, however, that these parameters
> were not chosen based on an exhaustive exploration of the parameter
> space, and should be seen only as an **educated guess** of what could be
> a sensible specification of multi-contrast registration weights.
> Inspection of registration quality is strongly recommended.

## 4.2 Longitudinal FreeSurfer

[FreeSurfer's longitudinal processing stream](https://surfer.nmr.mgh.harvard.edu/fswiki/FsTutorial/LongitudinalTutorial) is executed in three main
steps: 1) Cross-sectionally processs T1-weighted images of each session, 2) generate an unbiased
within-subject template across sessions and reconstruct it, and 3)
optimise the template reconstruction based on session-specific data.
Because both the within-subject template generated internally by
FreeSurfer and the previously generated within-subject templates for our 
quantitative tractography pipeline rely on mri_robust_template for rigid alignment, 
the resulting images are in spatial correspondence.

If only rigid alignment was used for the external within-subject
template generation, FreeSurfer's longitudinal stream can be executed
using its default workflow; if, however, the external within-subject
template was further refined using non-linear registration, this
template must be manually injected into FreeSurfer's longitudinal
processing stream, replacing the default rigid template. The sections
below outline the relevant FreeSurfer commands for running the
longitudinal pipeline in both cases, using either a rigid or a
non-linearly refined within-subject template.

> [!TIP]
> The execution of upcoming recon-all commands are optimised for the extraction of relevant outputs from a *single subject*. When processing multiple
> subjects across a cohort, efficiency can be significantly improved by parallelising single-threaded recon-all runs at the cohort level. 
> See [multi-threaded use of for_each](https://mrtrix.readthedocs.io/en/dev/reference/commands/for_each.html) for more information.

### 4.2.1 Reconstruction of session-wise T1-weighted images

**\[standard processing\]**

First, we cross-sectionally process the T1-weighted images for each session:

```bash
for_each -nthreads 2 tp* : recon-all \
  -i IN/T1w_norm_Warped.nii.gz \
  -sd IN/ \
  -s recon \
  -all
```

> [!NOTE]
> Both timepoints are processed here in parallel. See [multi-threaded use of ```for_each```](https://mrtrix.readthedocs.io/en/dev/reference/commands/for_each.html) for more information.

### 4.2.2 Base template reconstruction

#### 4.2.2.1 Rigid base-template reconstruction

**\[standard processing\]**

If rigid registration was performed, the default FreeSurfer base
template construction and reconstruction can be used:

```bash
SUBJECTS_DIR=template/

mkdir -p $SUBJECTS_DIR

for_each tp* : ln -sr \
  IN/recon \
  template/recon_IN

recon-all \
  -tp template/recon_tp1 \
  -tp template/recon_tp2 \
  -base template/recon_template \
  -all \
  -parallel \
  -openmp 8
```

#### 4.2.2.2 Non-linear base-template reconstruction

**\[pipeline-specific processing\]**

If non-linear registration was used, the processing stream needs to be
interrupted after the initial stage, and the externally generated
T1-weighted within-subject template injected. Then, the subsequent
stages are executed, reconstructing the non-linear T1-weighted template
instead.

First, run the initial stage of base-template construction:

```bash
SUBJECTS_DIR=template/

mkdir -p $SUBJECTS_DIR

for_each tp* : ln -sr \
  IN/recon \
  template/recon_IN

recon-all \
  -tp template/recon_tp1 \
  -tp template/recon_tp2 \
  -base template/recon_template \
  -autorecon1 \
  -parallel \
  -openmp 8
```

Now we can inject the previously generated non-linear T1-weighted
within-subject template into the longitudinal FreeSurfer stream. We will
rename the default template to keep it for reference, and replace it
with the non-linear template, which we resample to conform with
FreeSurfer specifications:

```bash
mv template/recon_template/mri/norm_template.mgz \
  template/recon_template/mri/norm_template_rigid.mgz

mri_vol2vol \
  --mov template/template_t1w_nonlinear.nii.gz \
  --targ template/recon_template/mri/norm_template_rigid.mgz \
  --o template/recon_template/mri/norm_template.mgz \
  --interp cubic \
  --regheader
```

After injection of the non-linear template, continue the base-template
reconstruction:

```bash
recon-all \
  -tp template/recon_tp1 \
  -tp template/recon_tp2 \
  -base template/recon_template \
  -autorecon2 \
  -autorecon3 \
  -careg \
  -parallel \
  -openmp 8
```

> [!NOTE]
> Injecting the non-linear template into the processing stream will now
> reconstruct this template instead of the original rigid template.
> However, FreeSurfer will still internally use the original linear
> transforms, rather than the warps used to generate the non-linear
> template. While this may seem counterintuitive, this approach is
> entirely consistent with [[Hoffmann2020]](https://archive.ismrm.org/2020/1050.html): although support for
> non-linear transforms exists within the pipeline, it has been found that
> their use can result in suboptimal surface placement. Since the base
> template serves merely as a starting point for further optimisation of
> vertex placements, the final output surfaces should still be
> appropriately fitted to cortices, despite the use of rigid transforms.
> Visual inspection of the final longitudinal outputs is strongly
> recommended. 

### 4.2.3. Longitudinal timepoint reconstruction

**\[standard processing\]**

Finally, optimise the base template to the longitudinal timepoint data:

```bash
for_each -nthreads 2 tp* : recon-all \
  -long template/recon_IN \
  template/recon_template \
  -all
```

> [!NOTE]
> Both timepoints are processed here in parallel. See [multi-threaded use of ```for_each```](https://mrtrix.readthedocs.io/en/dev/reference/commands/for_each.html) for more information.

The final outputs are robust, longitudinal grey matter reconstructions
for each timepoint, as well as a FOD template that lives within the same
output space, which we will use for further processing. To match the
naming convention used throughout the rest of the tutorial, we now
simply have to rename the transforms generated by the wrapper command.

If a rigid template was generated run:

```bash
for_each tp* : cp \
  template/transforms/IN/sub2temp_rigid.txt \
  template/transforms/IN.txt
```

If a non-linear template was generated run:

```bash
for_each tp* : mrconvert \
  template/transforms/IN/sub2temp_nonlinear.mif \
  template/transforms/IN_subject2template_deformation.mif
```

You can now **continue with step 2.2.2** (segmentation of different
tissue types) of the main tutorial.
